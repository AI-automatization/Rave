# SKILL: Brainstorm
# Структурированная генерация идей с последовательным анализом и отбором лучших решений.

---

## TRIGGER

`/brainstorm [тема]` — запустить мозговой штурм по любой теме:
- архитектурные решения
- UI/UX концепции
- фиксинг сложных багов (когда root-cause неочевиден)
- новые фичи / продуктовые идеи
- технический долг и рефакторинг

---

## ПРОТОКОЛ (5 фаз)

### Фаза 1 — DIVERGE (широкая генерация)
Генерируй минимум **6 идей** без самоцензуры. Включай:
- очевидные решения
- нестандартные / неожиданные
- радикальные (даже если кажутся неразумными)
- минималистичные (наименьшее изменение)
- долгосрочные (правильно, но сложно)

Формат каждой идеи:
```
💡 [Идея N]: [Название — 3-7 слов]
   Суть: [1-2 предложения]
   Плюс: [главное преимущество]
   Минус: [главный риск/стоимость]
```

### Фаза 2 — CLUSTER (группировка)
Объедини идеи по темам/подходам. Найди скрытые связи между ними.

### Фаза 3 — EVALUATE (оценка)
Оцени топ-3 идеи по матрице:

| Идея | Импакт (1-5) | Сложность (1-5) | Риск (1-5) | Score |
|------|-------------|----------------|-----------|-------|

Score = Импакт × 2 − Сложность − Риск

### Фаза 4 — SYNTHESIZE (синтез)
Можно ли скомбинировать лучшие элементы нескольких идей в одно решение?
Опиши гибридный вариант если он лучше отдельных.

### Фаза 5 — RECOMMEND (рекомендация)
```
🎯 РЕКОМЕНДУЮ: [Название]
   Почему: [2-3 причины]
   Первый шаг: [конкретное действие — файл:функция или команда]
   Риск: [что может пойти не так]
   Альтернатива если не сработает: [запасной вариант]
```

---

## ПРАВИЛА

- Не переходи к реализации без явного подтверждения пользователя после Фазы 5
- Если тема затрагивает shared/* — напомни о lock-протоколе
- Если идея затрагивает чужую зону (Backend↔Mobile) — отметить `⚠️ cross-zone`
- Используй sequential-thinking MCP если доступен (глубже анализирует зависимости)
- После выбора идеи → создать TASK_SPEC через `spec-driven-implement.md`
