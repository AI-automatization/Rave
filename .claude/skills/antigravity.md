# Antigravity Skill — Второе мнение и Self-Critic

**ПРАВИЛО: перед нетривиальной работой и после реализации — прогнать решение через `agy`.**

`agy` = агентный CLI от Google (Antigravity), залогинен, `/Users/saidazim/.local/bin/agy`.
Использовать как независимого ревьюера: он не видит мой контекст, поэтому ловит то,
что я пропускаю из-за tunnel vision.

---

## Запуск

```bash
agy -p "<промпт>"                       # single-shot, печатает ответ (основной)
agy -c "<промпт>"                       # продолжить последний разговор
agy --model "Claude Opus 4.6 (Thinking)" -p "..."   # выбрать модель
agy models                              # список моделей
```

**Модели:** Gemini 3.5 Flash (Low/Medium/High), Gemini 3.1 Pro (Low/High),
Claude Sonnet 4.6 (Thinking), Claude Opus 4.6 (Thinking), GPT-OSS 120B.

---

## Когда вызывать (ОБЯЗАТЕЛЬНО)

| Фаза | Зачем | Запрос |
|------|-------|--------|
| Перед сложной задачей (≥3 файла / архитектура) | найти дыры в плане | "Ты строгий ревьюер. План: <план>. 3 слабых места — где сломается. Кратко, RU." |
| После реализации | поймать упущенное | "Ревью diff: <diff>. Что упустил по корректности/безопасности?" |
| Архитектурное решение | альтернативы + риски | "Подход: <X>. Альтернативы и риски каждой. RU." |
| Застрял на баге | гипотезы root cause | "Симптомы: <...>. Пробовал: <...>. Топ-3 гипотезы причины." |

Пропускать для: typo, 1-строчных правок, config, messages/*.json.

## Workflow self-critique

```
1. Сформулировать своё решение/план кратко (не весь контекст — только суть)
2. agy -p "Ты строгий ревьюер. <решение>. Назови слабые места. Кратко, по-русски."
3. Прочитать критику → отделить валидное от шума
4. Валидные замечания → исправить ПЕРЕД тем как отдать результат юзеру
5. Спорные → упомянуть юзеру как риск, не молча игнорировать
```

**Важно:** agy — советник, не начальник. Его критику фильтровать через знание проекта
(CLAUDE.md, зоны, существующие паттерны). Не следовать слепо.

---

## Пример

```bash
agy -p "Ты строгий ревьюер. Вот план рефактора god-файла videoEvents.handler.ts (520 строк) на 3 модуля: play/pause handlers, seek/sync handlers, buffer handlers. Назови 3 риска. Кратко, RU."
```
