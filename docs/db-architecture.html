💡 Здесь показано — какие поля комбинируются между собой, какие проверки происходят по шагам, и что мы получаем на выходе.
🔐 Вход в аккаунт (Login) AUTH
email + password = accessToken (15 мин) + refreshToken (30 дней)
1
Найти пользователя по email
Ищем в auth.users по полю email
Есть уникальный индекс → поиск мгновенный
Не найден → 404 Пользователь не существует
↓
2
Проверка блокировки и подтверждения почты
isBlocked = true → 403 Аккаунт заблокирован
isEmailVerified = false → 403 Подтвердите почту
↓
3
Защита от перебора пароля (Redis)
Проверяем Redis: login_attempts:{email}
Если попыток ≥ 5 → 429 Аккаунт заблокирован на 15 минут
↓
4
Проверка пароля
Поле passwordHash скрыто по умолчанию — запрашивается явно
bcrypt.compare(password, passwordHash)
Не совпадает → 401 Неверный пароль + счётчик +1 в Redis
↓
5
Выдаём токены
accessToken = JWT RS256 { userId, email, role } — живёт 15 минут
refreshToken = случайные байты → хэшируем → сохраняем в refreshtokens
Redis: удаляем счётчик попыток // сброс при успехе
📝 Регистрация (Register) AUTH
email + password + username = новый аккаунт + письмо с кодом
1
Проверяем уникальность
Ищем в auth.users по email → 409 Почта уже занята
Ищем по username → 409 Никнейм уже занят
↓
2
Хэшируем пароль и создаём запись
passwordHash = bcrypt(password, соль 12 раундов)
emailVerifyToken = crypto.randomBytes(32)
Создаём запись в auth.users
↓
3
Создаём профиль в сервисе пользователей
Один документ в cinesync.users — учётка + профиль сразу
// одна база, один документ — authId больше не существует
↓
4
Отправляем письмо
На почту уходит ссылка с emailVerifyToken
201 Аккаунт создан — проверьте почту
✉️ Подтверждение почты AUTH
emailVerifyToken = isEmailVerified = true → можно войти
1
Пользователь переходит по ссылке из письма
Ищем в auth.users по emailVerifyToken
// поле скрытое — запрашиваем явно через .select()
↓
2
Проверяем срок действия
emailVerifyTokenExpiry < текущее время → 410 Ссылка истекла
// можно отправить новую ссылку
↓
3
Активируем аккаунт
isEmailVerified = true
emailVerifyToken = null // очищаем, больше не нужен
Теперь пользователь может войти
🔄 Обновление токена (без повторного входа) AUTH
refreshToken = новый accessToken (без ввода пароля)
1
Хэшируем входящий токен и ищем в БД
tokenHash = SHA256(refreshToken)
Ищем в refreshtokens по tokenHash
Не найден → 401 Токен недействителен (выход)
↓
2
Проверяем срок действия
expiresAt < сейчас → 401 Сессия истекла
// MongoDB TTL индекс удалит запись автоматически
↓
3
Ротация: старый удаляем, новый создаём
Удаляем старую запись из refreshtokens // защита от кражи
Новый accessToken = JWT(userId) 15 мин
Новый refreshToken → сохраняем в refreshtokens
🎉 Войти в комнату просмотра PARTY
inviteCode + userId (из токена) = подключение к комнате + синхронизация видео
1
Находим комнату по коду
Ищем в watchpartyrooms по inviteCode
Уникальный индекс → мгновенно
Не найдена → 404
↓
2
Проверки перед входом
status = 'ended' → 404 Комната закрыта
members.length ≥ maxMembers → 403 Комната заполнена
isPrivate + password: bcrypt.compare(введённый пароль)
↓
3
Добавляем участника и синхронизируем
Добавляем userId в массив members
Socket.io: подключаем к комнате
Отправляем текущее состояние видео: { currentTime, isPlaying }
▶️ Продолжить просмотр CONTENT
userId + videoUrl = позиция с которой остановились
1
HomeScreen: список незавершённых видео
Ищем в watchprogress где userId = я AND percent < 90
Сортировка по updatedAt (последние наверх)
Составной индекс { userId, updatedAt } → быстро
↓
2
Сохраняем позицию каждые 5 секунд
Upsert в watchprogress по ключу { userId, videoUrl }
// уникальный индекс = одна запись на одно видео
Обновляем currentTime и percent
↓
3
При открытии видео — перематываем
Плеер получает currentTime → перематывает на нужную секунду
// пользователь продолжает с того места где остановился
🤝 Отправить заявку в друзья USER
requesterId + receiverId = запись в friendships + push-уведомление
1
Проверяем что заявки ещё нет
Ищем в friendships: { requesterId, receiverId }
Уже есть → 409 Заявка уже отправлена
↓
2
Создаём запись
Создаём в friendships: { requesterId, receiverId, status: 'pending' }
// уникальный индекс защищает от дублей на уровне БД
↓

Отправляем уведомление

FCM push на устройства из fcmTokens[]

⚡ Redis — хранилище в оперативной памяти. Используется для кэша, блокировок и очередей. Данные теряются при перезапуске (не критично — всё восстанавливается из MongoDB).
login_attempts:{email} TTL 15 минут
Что хранит
Счётчик неудачных попыток входа
Значение
1, 2, 3, 4, 5…
Логика
При 5 и более попытках → 429 ошибка, вход заблокирован на 15 минут
Сброс
Удаляется при успешном входе
Пример ключа
login_attempts:saidazim@mail.com
trending:{limit} TTL 10 минут
Что хранит
Список популярных фильмов (JSON)
Логика
Есть в Redis → отдаём сразу. Нет → берём из MongoDB, кладём в Redis, отдаём
Зачем
HomeScreen запрашивает при каждом открытии — Redis в 100× быстрее MongoDB
Пример ключа
